Mango Astro 站点管理与设置教程

适用站点：https://mango-astro.pages.dev（mango-astro 工程） 最后更新：2026-11-07

0. 先认清这个站由哪几块组成

组成部分 是什么 在哪
Astro 静态站点生成器，把 Markdown 和组件编译成 HTML 本机 /Users/ming/mango-astro
GitHub 仓库 存放源码，也是 CMS 写入文章的地方 github.com/htianshi45/mango-astro（Private）
Cloudflare Pages 托管编译后的静态文件 mango-astro.pages.dev
Sveltia CMS 浏览器里的写文章后台（中文界面） /admin/
OAuth 网关 让 CMS 能安全登录 GitHub 的中间层 auth.840428.xyz（Cloudflare Worker）

数据流是这样的：

你在 /admin/ 写文章
   → Sveltia 调 GitHub API，把 Markdown 提交进仓库
   → 仓库出现新 commit
   → （若接了 Git 构建）Pages 自动重新编译 → 线上更新

关键认知：这是静态站点，没有「后台设置面板」。除了文章内容，所有站点设置（站名、导航、Banner、备案号、主题色）都写在源码文件里。改完必须重新构建 + 部署才生效。

1. 三种操作，先分清

你想做的事 用什么 要改代码吗 要重新部署吗
写文章、改文章、传图 /admin/ 后台 不用 看是否接了 Git 构建
改站名、导航、Banner、备案号、颜色 改源码文件 要 要
让改动上线 npm run build + 部署 — —

2. 写文章（最常用）

2.1 用后台（推荐）

  1. 打开 https://mango-astro.pages.dev/admin/
  2. 点 「使用 GitHub 登录」 → 授权（第一次需要，之后长期有效）
  3. 左侧 文章 → 右上角 新建
  4. 按下面第 2.3 节填字段
  5. 右上角 保存（会直接提交到 GitHub）

如果不想走 OAuth 弹窗，登录页还有 「使用访问令牌登录」，粘贴一个 ghp_ 开头的令牌即可。

注意：后台保存 = 直接 commit 到 GitHub，不会写你本地硬盘。本地要 git pull 才能看到。

2.2 手动写 Markdown

在 src/content/posts/ 新建 你的文件名.md，开头必须有 frontmatter：

---
title: 文章标题
description: 一句话摘要（会显示在卡片上）
pubDate: 2026-11-07
heroImage: /images/test-1.jpg
images:
  - /images/test-1.jpg
  - /images/test-2.jpg
  - /images/test-3.jpg
author: 大明白
avatar: /images/avatar-1.svg
tags:
  - 摄影
  - 风景
category: 风景
sticky: 0
views: 0
comments: 0
likes: 0
draft: false
---

正文从这里开始，支持标准 Markdown。

2.3 字段说明（对应 src/content/config.ts）

字段 类型 必填 说明
title 字符串 ✅ 文章标题
description 字符串 — 卡片摘要，不填则卡片不显示摘要行
pubDate 日期 ✅ 发布日期，决定排序
updatedDate 日期 — 更新日期
heroImage 路径 — 封面图，用于热门文章小工具
images 字符串数组 — 九宫格图片，最多展示 9 张
author 字符串 — 默认 Mango，建议改成你的名字
avatar 路径 — 作者头像
tags 字符串数组 — 标签，会生成 /tags/标签名 页面
category 字符串 — 分类，会生成 /categories/分类名 页面
sticky 数字 — 置顶权重，越大越靠前，0 表示不置顶
views / comments / likes 数字 — 静态展示数字（不是真实统计）
draft 布尔 — true 则不发布

2.4 图片怎么放

  • 图片统一放 public/images/，引用时写 /images/文件名.jpg
  • 文件名建议英文/数字，中文也能用但 URL 会被编码
  • 九宫格规则（src/components/PostImages.astro）：
  • 1 张 → 单张大图（16:9）
  • 2 张 → 两列
  • 3–9 张 → 三列方形
  • 超过 9 张 → 只显示前 9 张，第 9 张盖一层 +N 角标，点开可翻看全部
  • 建议单张压缩到 300 KB 以内，宽度 1200–1600 px 足够
  • 点击图片会全屏放大（从缩略图原位放大，支持左右滑、双击缩放）

3.1 改导航菜单的具体写法

src/config/site.ts 的 siteConfig.navItems：

导航已改为 Firefly 风格的分组下拉：三段式胶囊卡片（Logo｜居中菜单｜右侧工具按钮），桌面 hover / 点击 / 键盘聚焦都能展开二级菜单，窄屏收进右侧抽屉。

navItems: [
  { name: '主页', href: '/', icon: 'bi-house' },
  {
    name: '文章', href: '#', icon: 'bi-journal-text',   // href 为 '#' = 只作下拉父级
    children: [
      { name: '文章归档', href: '/archive', icon: 'bi-archive', page: 'archive' },
      { name: '说说', href: '/moments', icon: 'bi-chat-square-dots', page: 'moments' },
    ],
  },
  { name: '关于我', href: '/about', icon: 'bi-info-circle' },
  { name: 'GitHub', href: 'https://github.com', icon: 'bi-github', external: true },
],
  • name 显示文字，href 链接；icon 用 Bootstrap Icons 类名
  • children 存在即自动生成二级下拉菜单；父级 href: '#' 时不会跳转
  • page 关联页面开关；开关设为 false 时该项（含子项）自动消失，分组若无可用子项整组隐藏
  • external: true 会新窗口打开并加 noopener noreferrer
  • 加一项就复制一行，删一项就删一行；更多见第 11.1 节

3.2 改轮播的具体写法

src/config/banner.ts：

export const banners: BannerItem[] = [

  • 图片建议 900×350 或 16:9 横图（aspect-ratio: 900/350，宽屏变 21/9）
  • 用方图会被裁切，只剩中间一条
  • 不要填网页链接当图片，必须是图片文件

4. 主题色怎么改（三处要一起改）

主色不是只改一个地方，目前有三处硬编码：

位置 内容
tailwind.config.mjs 第 8–13 行 mango: { light, DEFAULT, dark, hover }
src/components/Header.astro 搜索按钮 hover 色 #4270f5
src/components/Footer.astro Powered by 链接 #4270f5

改色建议：选定一个主色（如 #e8590c 橙），然后：

mango: {
  light: '#ff8a4c',    // 浅一档，用于深色模式下的链接
  DEFAULT: '#e8590c',  // 主色
  dark: '#b8440a',     // 深一档
  hover: '#a33d08',    // hover 态
},

再把 Header.astro / Footer.astro 里的 #4270f5 一起换成 #e8590c，否则会有颜色不一致。

6. 后台维护

6.1 两种登录方式

方式 操作 适合
GitHub OAuth 点「使用 GitHub 登录」→ 授权 日常用，一次授权长期有效
访问令牌 点「使用访问令牌登录」→ 粘 ghp_ 令牌 OAuth 出问题时的备用通道

6.2 网关自检

后台登录不了，先查网关是否健康：

curl https://auth.840428.xyz/health

正常应返回：

{ "ok": true, "client_id_configured": true, "client_secret_configured": true,
  "allowed_origins": ["...", "https://mango-astro.pages.dev", "https://mango.840428.xyz"],
  "callback_url": "https://auth.840428.xyz/callback" }

两个 configured 必须都是 true，否则去 oauth-gateway/ 重新 wrangler secret put。

6.3 换 OAuth 密钥

# 1. GitHub → Settings → Developer settings → OAuth Apps → Mango CMS
#    点 Generate a new client secret，复制新的，旧的 Delete
# 2. 填进网关
cd /Users/ming/mango-astro/oauth-gateway
wrangler secret put GITHUB_CLIENT_SECRET

换完不影响已登录状态。

6.4 网关重新部署

改过 oauth-gateway/worker.js 或 wrangler.toml 后：

cd /Users/ming/mango-astro/oauth-gateway
wrangler deploy

7. 备份与回滚

这个工程是 git 仓库，每次改动前先提交，出问题能一键回退。

cd /Users/ming/mango-astro
git add -A
git commit -m "改了什么"
git push

回滚：

# 看历史
git log --oneline

# 撤销某一次提交（生成一个反向提交，安全）
git revert <commit-hash>
git push

# 只恢复某个文件到某个版本
git checkout <commit-hash> -- src/components/Header.astro

CMS 与本地的关系：后台改文章是提交到 GitHub，本地要 git pull 才同步。如果本地也改了同一篇，pull 会冲突，先提交本地改动再 pull。

8.1 CMS 写入的常见坑（重要）

后台是直接在 GitHub 上写 Markdown 的，不会经过本地校验。实际踩过两个坑，现已分别做了容错和拦截：

坑 表现 现在的处理
可选「更新日期」留空 CMS 写出 updatedDate: ''，z.coerce.date() 得到 Invalid Date，整站构建直接失败 src/content/config.ts 的 optionalDate 用 z.preprocess 把空串归一化为 undefined
「URL 别名 / slug」随手填值 Astro 把 frontmatter 的 slug 当成路由别名。曾把 coffee-shops.md 填成 1321，文章网址静默变成 /posts/1321/，旧链接全部 404 scripts/check-content.mjs 在每次 npm run build 前体检，别名与文件名不一致就以非零码阻断构建

因此编辑已有文章时：「URL 别名」字段请保持与文件名一致（如 coffee-shops），不要改动它；只有新建文章时才需要填一个英文短名，它同时决定文件名和网址。后台该字段下方也写了同样的提示。

体检脚本覆盖：URL 别名一致性、别名重复、title / pubDate 必填、日期合法性、frontmatter 是否闭合。单独运行：

npm run check:content

它会列出问题文件并给出改法。npm run build 已把它串在 astro build 之前，所以构建通过就代表这些内容层面是干净的。

11. 新功能维护：说说 / 书签导航 / 收藏四库

本轮参考 Firefly 主题补了四块功能：分组导航栏、说说与首页混合时间流、书签导航、四个收藏库。除书签导航是配置文件外，其余内容都能在 Sveltia CMS 后台维护。

11.1 导航栏与页面开关

导航栏由 src/config/site.ts 的 navItems 驱动（写法见 3.1）。渲染逻辑在 src/components/Header.astro：桌面是三段式毛玻璃胶囊 + 分组下拉，窄屏（<1024px）收进右侧抽屉，抽屉里的二级菜单用原生 <details> 折叠。

当前页面开关（pageToggles）共 8 个：

开关 控制 关闭后的联动
moments 说说 导航/页脚入口隐藏、/moments 返 404、sitemap 排除、首页回到纯文章流
bookmarks 书签导航 导航/页脚入口隐藏、/bookmarks 返 404、sitemap 排除
favorites 收藏四库 + 总览 导航里 5 个收藏入口隐藏、5 个页面返 404、sitemap 排除
archive / tags / search / download / map 原有页面 同上

改法：在 src/config/site.ts 把对应值改成 false，重新构建部署即可，visibleNavItems() 会递归过滤子菜单，分组无可用子项时整组隐藏。

11.2 首页混合时间流

src/utils/feed.ts 把 posts 和 moments 归一成同一种 FeedEntry，再按发布时间倒序合并。index.astro 与 page/[page].astro 共用同一份结果，所以第一页和第二页顺序不会错位。

siteConfig.home 有三个开关：

配置 默认 说明
mixMode 'timeline' 严格按发布时间倒序合并；改成 'alternate' 会强制文章/说说一比一交替（同类型内部仍按时间倒序）
stickyFirst false 置顶项是否插队到最前。默认 false：严格按时间交替，置顶只用徽标体现
showTypeBadge true 是否在卡片上显示「文章 / 说说」类型徽标

postsPerPage 现在是混合流的每页条数（文章 + 说说一起计数）。示例说说的日期特意穿插在现有文章之间，所以首页打开就是「文章—说说—文章—说说」。

订阅源也接了这份混合流：feed.includeMoments 默认 false（只订阅文章），改成 true 后说说会以「短内容 · 说说」的标题进 RSS / Atom，链接指向 /moments/#moment-<id>。

11.3 写说说

后台：登录 /admin/ → 左侧「说说」→ 新建。文件名由发布时间自动生成，不用手填 ID。

手动：在 src/content/moments/ 新建 Markdown，例如 2026-11-07-1.md：

---
published: 2026-11-07 14:30:00
pinned: false
location: 杭州 · 西湖
tags:
  - 随手拍
---

今天天气不错。

![照片](/images/uploads/photo.jpg)
字段 必填 说明
published 是 发布时间，决定首页排序
pinned 否 置顶徽标；默认不插队（见 11.2）
location 否 显示在卡片底部
tags 否 标签，链接到标签页
author / avatar / draft / updatedDate 否 有默认值

正文里直接写 Markdown 图片；图片会自动抽出来走九宫格和全站灯箱，正文只渲染文字。pinned: true 只加徽标，draft: true 不会出现在任何页面。

/moments/ 是独立归档页：按年份分组、支持关键词搜索和年份下拉，都是浏览器端过滤，无需后端。

11.4 书签导航

数据在 src/config/bookmarks.ts（仿 Firefly 的 booknavConfig.ts），不在 CMS 里——它是 TS 配置，用 CMS 的 Markdown 编辑器打开会写坏文件。

{
  id: 'dev', name: '开发', icon: 'bi-code-slash', desc: '写代码时离不开的站点', weight: 100,
  items: [
    { title: 'GitHub', url: 'https://github.com', desc: '全球最大的代码托管平台', icon: 'bi-github', weight: 10 },
    { title: 'MDN Web Docs', url: 'https://developer.mozilla.org', desc: '最权威的 Web 文档', weight: 9 },
  ],
}
  • weight 越大越靠前（分组与组内条目分别排序）
  • icon 可填 bi-* 图标名、图片路径或 URL；留空则自动取目标站点 favicon
  • favicon 接口在 bookmarksPageConfig.favicon.api，取不到时自动回退名称首字母，不会裂图
  • applyNote 是页脚说明，留空则不显示

/bookmarks/ 页头有搜索框与分类锚点，都是纯前端过滤。

11.5 收藏夹 / 书架 / 片库 / 音乐库

参考 Firefly 的番剧页模型，用一个 collection 驱动四个页面：数据在 src/content/favorites/*.md，分类元数据在 src/config/favorites.ts。

页面 分类键 封面比例 状态标签
/favorites/bookmarks bookmarks 收藏夹 1:1 待读 / 在读 / 已读 / 精选
/favorites/books books 书架 2:3 想读 / 在读 / 读过 / 最爱
/favorites/movies movies 片库 2:3 想看 / 在看 / 看过 / 最爱
/favorites/music music 音乐库 1:1 想听 / 在听 / 听过 / 循环

/favorites/ 是总览：四个分类卡片（数量 + 完成率进度条）+ 最近添加。分类页有 Tab、状态筛选、搜索、统计条（平均评分 / 已完成 / 进行中 / 已评分）。

一条收藏的 frontmatter：

---
slug: 'book-1'
title: 置身事内
category: books
cover: /images/favorites/book-1.svg
description: 从地方政府的角度理解中国经济是怎样运转的
status: done          # wish | doing | done | favorite
rating: 9             # 0–10，0 为未评分
progress: 100         # 0–100，书架/片库显示进度条
url: ''
creator: 兰小欢
year: '2021'
tags: [经济, 非虚构]
addedAt: 2024-09-18
weight: 10
---

正文写短评，卡片里可折叠展开。

封面示例是本地生成的渐变 SVG（public/images/favorites/），不依赖外链；留空 cover 会显示名称首字母占位。想加第五个库，在 favoriteCategories 里加一项，动态路由会自动生成新页面。

11.6 CMS 字段与构建前体检（重要）

public/admin/config.yml 现在有 3 个 collection：posts（文章）、moments（说说）、favorites（收藏条目）。

CMS 保存已有条目时会重写整个 frontmatter，未在 fields 里列出的字段会被抹掉。 所以每个 collection 都把对应 schema 的字段列全了；以后给 schema 加字段，必须同步改 config.yml。

npm run check:content（已串进 npm run build）现在覆盖三个目录：URL 别名与文件名一致性、别名重复、必填字段、日期合法性、category 枚举、rating/progress 数值范围。当前输出：

[check-content] ✓ 文章 16 · 说说 8 · 收藏 10 全部通过

说说与文章/收藏有一处不同：说说的 fields 里刻意没有 slug（用发布时间自动生成文件名），避免 Astro 把 frontmatter slug 当成条目 ID；文章和收藏则保留 slug 字段，编辑时务必保持与文件名一致，详见 8.1。
