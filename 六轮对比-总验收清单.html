Mango 主题 · 六轮对比与总验收清单

对比对象：http://localhost:4321/（下称「本地 v6」）vs https://mango.huitheme.cn/（WordPress 原版） 浅色对照图：对比-原版vs新版-v6.png（上原版 / 下 v6，940×1930） 暗色对照图：对比-暗色-原版vs-v6.png（首次完成暗色验证，见 §3） 生成时间：2026-11-07 00:15 ｜ 基准 CSS：Theme Version: 1.6.20241202 历轮：v1《一比一复刻-差距清单》→ v2 → v3 → v4 → v5 → 本份（总验收）

1. 结论：可以收工了 ✅

第五轮点名的 3 处「代码写了、实际没生效」，本轮全部补实；素材也做了一次大换血，视觉上已经很难与原版区分：

v5 遗留 v6 状态 验证
分页永不触发 ✅ 补实 文章 8 → 16 篇，/page/2/ 实测 200，首页出现 pagination-nav 与页码，npm run build 51 页
Giscus 占位参数 ✅ 补实 新增 src/config/comment.ts（enabled / repo / repoId / category / categoryId 可配置）；未配置时渲染「评论未启用」占位块，不注入会报错的脚本；文章页实测出现占位块
顶栏多余按钮 ✅ 补实 Header.astro:201-206 改成 @media(min-width:1024px){#mobile-menu-toggle, .header-icon-btn.lg\:hidden{display:none!important}} 一次覆盖，并把 display:flex 移出 scoped CSS 交给 Tailwind flex 类 → 1440px 顶栏右侧只剩 2 个圆按钮

同时把上轮列的细节也收了：顶栏搜索改成点图标 → 顶部展开 120px 搜索条（#c_sousuo{height:0} → .open{height:120px}、.ss_a 3px #ddd 边框 / 40px 行高），与原版一致；灯箱补了按 data-gallery 分组的上一张/下一张；侧栏热门文章回到 3 条；bg-wave.svg 换成 120×120、#d8d8d8、1~1.1 线宽，暗色下水波纹清晰可见。

素材换血：logo 改橙黄芒果、banner 改桌面工作台（显示器 + 台灯 + 绿植）、头像改真人风格、首卡标题改「也许是最实用的万兆NAS 超长文分页」、九宫格出现 +23 —— 对照图上下两半的作者名、标题、角标、侧栏条数已经能对上。

达成度：v5 约 95% → v6 约 98%。剩余的 2% 是内容素材与上线配置，不再是复刻缺陷。

两次关键教训已沉淀：① Tailwind 3 会 purge @layer components 内未被 content 扫描到的自定义类；② Astro scoped CSS 的 [data-astro-cid] 属性选择器特异性 (0,2,0) 会压过 Tailwind 响应式工具类 (0,1,0)。这两条在 v3、v4 各造成过一次返工。

3. 首次暗色验证 🌙（前五轮一直缺的一项）

前五轮对照只做了浅色，本轮用 Chrome DevTools Protocol 补上了：

# 本地：先写 localStorage 再 reload，让 ThemeScript 生效
/Users/ming/.workbuddy/binaries/python/envs/default/bin/python /tmp/mango_dark_shot2.py \
  "http://localhost:4321/" /tmp/mango-v6-dark.png local

# 原版：手动给 html/body 加 .dark 类（WordPress 主题同款选择器）
/Users/ming/.workbuddy/binaries/python/envs/default/bin/python /tmp/mango_dark_shot2.py \
  "https://mango.huitheme.cn/" /tmp/mango-demo-dark.png original

验证结果（/tmp/mango-v6-dark.png）：document.documentElement.className = dark、localStorage.theme = dark ✅；顶栏 #151516、背景 #191919 + 清晰水波纹、卡片与侧栏 widget #212121、正文浅灰、标签与 +23 角标可辨、灯泡按钮黄色、橙黄芒果 logo、轮播与九宫格图片正常 —— 暗色模式没有漏改，也没有 v4 那个「整体发灰」的问题。

⚠️ 对照局限（如实说明）：原版暗色截图是用 CDP 手动加 .dark 类得到的，且 --no-proxy-server 下原版的外链 banner / 侧栏缩略图未加载（显示为黑块）。所以 对比-暗色-原版vs-v6.png 只能用于比对色板与布局（背景/顶栏/卡片/文字/间距），不能用于比对图片区域。若要做严格的暗色视觉回归，需先让原版外链图片正常加载再截一次。

4. 剩余 5 项小差异 🧩

# 位置 v6 现状 说明
1 首卡摘要 多一行「从选型到组装，再到系统部署，一篇把万兆 NAS 讲透的长文。」 原版首卡无摘要。nas-build-guide.md 的 description 清空即可（v4 曾对 welcome.md 这么做过，本轮首卡换了文章又带回来了）。这是唯一一处肉眼可见的版式差异
2 图片素材 九宫格是风景照、侧栏大图是砖墙木纹、banner 显示器里是风景拼图 原版对应位置是 NAS 机器/桌面实拍。形态、数量、+23 全对，纯内容层面

4 备案号 京ICP备00000000号 占位值，上线前必须换成真实备案号或移除
5 WordPress 动态功能 浏览量/点赞数写在 frontmatter、评论走 Giscus 原版是数据库实时计数 + AJAX 点赞。静态站做不到，属第一轮就约定的「需替代」项，不算复刻缺陷

6. 上线前检查清单 🚀

复刻已经完成，接下来是把它真正变成一个可访问的站点。按优先级：

  1. 必须 - [ ] 清空 nas-build-guide.md 的 description（对齐原版首卡无摘要） - [ ] 替换 京ICP备00000000号，或在没有备案时移除该行 - [ ] 若要用评论：准备公开 GitHub 仓库 + 开启 Discussions → 到 https://giscus.app/ 取 repoId / categoryId → 填 src/config/comment.ts 并把 enabled: true - [ ] 全站外链图片已本地化（当前 test-*.jpg 等均在 public/images/，✅ 已完成）
  2. 建议 - [ ] 把 site_url / canonical / RSS / OG 等站点级配置换成正式域名（工程里若有 astro.config.mjs 的 site 需一并改） - [ ] 跑一次链接巡检：npm run build 后扫 dist/**/*.html 里的 href，确认无 404、无 href="#" - [ ] 375px / 768px 移动端各截一次（本轮对照只做了 1440px） - [ ] 中文搜索目前是客户端简单包含匹配；若文章继续增多，可换 Pagefind（注意中文分词限制，参考 Firefly 项目那次的结论）
  3. 部署（工程里已有 wrangler.toml / DEPLOYMENT.md） - [ ] npm run build → dist/ - [ ] Cloudflare Pages：wrangler pages deploy dist --project-name <name> --branch main，或连 GitHub 自动构建 - [ ] 绑定自定义域名 + 确认 CNAME 与 SSL 生效
