与优化路线图

对照 Mango 官方主题 1.1 的功能清单、Astro 5 官方能力与本机实测数据，逐项核对站点现状，给出 27 项可落地的优化与功能。

0评论系统
15 / 16首页图片缺尺寸声明

一句话结论：复刻程度已经很高——Mango 官方 9 项核心特性里 7 项到位，视觉与交互基本一比一；但作为「一个真能长期运营的博客」，还缺三样硬东西：评论、真实数据（阅读/点赞）、全文搜索。

另外有一处不太显眼但影响面最大的技术债：全站图片走 public/ 原图直出，既没有 WebP/AVIF，也没有 srcset 和宽高声明，还把 356 KB 的 banner 放在首屏；同时所有静态资源的 cache-control 都是 max-age=0，等于每次访问都要回源验证。这三件加起来，比任何新功能都更值得先做。

04优化与功能清单

27 项，按「投入产出比」分三档。P0 = 半天到一天就能做完、立刻见效；P1 = 让博客真正「活」起来；P2 = 体验打磨。

P0 性能与 SEO 地基 合计约 1.5 天 · 无新依赖（除 sharp）

1. 配 _headers，让缓存真正生效

30 分钟

新建 public/_headers：/_astro/* 用 immutable, max-age=31536000（文件名自带哈希，绝对安全）；/images/* 用 7 天；/fonts/* 用 30 天。

收益：回访用户从「每次回源验证 92 KB CSS + 228 KB 字体」变成直接命中本地缓存，二次访问基本零请求。现状：全部 max-age=0, must-revalidate。

2. 接 astro:assets 图片管线

半天

安装 sharp，把封面/说说图从 public/ 迁到 src/assets/，用 <Image> 或 getImage() 输出 WebP + 三档 srcset（400 / 800 / 1200），自动带 width/height。

  • banner 两只图先单独压到 < 100 KB（现在 561 KB）
  • 列表缩略图按卡片实际尺寸出 340px 版本
收益：首页图片从 716 KB 降到约 200 KB（−70%），CLS 归零。代价：内容里写的是 /images/… 绝对路径，需要一次批量迁移 + 兼容旧路径。

3. 图标字体子集化

1 小时

统计实际用到的约 40 个 bi-* 类名，用 fonttools pyftsubset 裁出子集字体，或改用内联 SVG sprite。

收益：228 KB → 约 15–25 KB，每个页面都省 200 KB。

4. robots.txt 接管 + sitemap 加 lastmod

30 分钟

新建 public/robots.txt 声明 Sitemap: https://…/sitemap.xml；在 src/pages/sitemap.xml.ts 里补 lastmod（取 updatedDate || pubDate）。

收益：搜索引擎能识别更新频率，新文章收录更快。现状：robots 是 CF 默认注入的，完全没提 sitemap。

5. 社交分享大图（OG Image）

2 小时

现在 og:image 指向 logo.svg——分享到微信/Telegram/X 时是一张空白方图。用 satori 或 @vercel/og 在构建期给每篇文章生成 1200×630 的标题卡。

收益：分享卡片的点击率差异极大，这是纯视觉收益。

6. 相关文章改按标签重合度打分

1 小时

现在只按 category 匹配，没分类时兜底「最新 5 篇」——等于随机推荐。改成 标签交集数 × 2 + 同分类 × 1 + 时间衰减 打分取前 5。

落点：src/pages/posts/[slug].astro 第 29–35 行。

7. 搜索索引外置

45 分钟

把 searchData 从 define:vars 内联改成构建期输出 /search-index.json，页面首次聚焦搜索框时再 fetch。

收益：实测搜索页 HTML 25.8 KB → 21.6 KB，更重要的是索引变成可独立缓存的资源，搜索页重复访问不再重复下载；后续接 Pagefind 或扩到说说/收藏也只需改这个数据出口。
P1 让博客「活」起来 合计约 4–6 天 · 这一步才叫真正的博客

1. 评论系统 最关键

2–4 小时接入

三条路选一条：

  • giscus（推荐）：基于 GitHub Discussions，零后端、零成本、有暗色主题、支持反应表情。需要仓库 public + 装 giscus App。
  • Waline：支持匿名评论、表情、邮件提醒，需要一台小服务器或 Vercel 部署 + 数据库。
  • Twikoo：国内访问快，可挂 Cloudflare D1（新版已支持）。

挂载点：文章页 .post_author 之后、说说卡片展开后。

为什么最关键：没有评论的博客只是「日志展示器」。而且评论一旦有了，最近评论小工具、评论数排序、互动数据全都跟着解锁。

2. 真实阅读量与点赞

1 天

用 Cloudflare Pages Functions + KV（或 D1）存计数：POST /api/view/:slug 自增，页面加载时异步读；点赞按 IP+UA 哈希去重。

更省事的替代：只接 Umami / Cloudflare Web Analytics 拿真实 PV，前端数字仍静态——但至少「热门文章」能基于真实数据。

现状：views: 19428 这类数字写死在 frontmatter 里，热门排行永远不变。

3. Pagefind 全文搜索

半天

构建后跑 pagefind --site dist，前端 /pagefind/pagefind.js 懒加载。中文需要开 --force-language zh 并接受单字分词，或配 jieba 预处理。

收益：搜索从「标题+描述」升级到「正文全文」，支持中文分词、结果高亮摘要、按标签过滤。索引按需分片加载，不拖慢首屏。

4. 「加载更多」替代纯翻页

半天

复用 src/pages/page/[page].astro 的静态分页：滚动到底时 fetch('/page/2/') 解析 DOM 取卡片追加，URL 用 history.replaceState 同步。保留 <noscript> 与原分页链接做 SEO 兜底。

这是官方主题的 ajax 翻页特性，纯前端即可实现，不需要后端。

5. 最近评论小工具

依赖第 1 项

giscus 提供 GraphQL 接口，构建期或客户端拉最近 5 条，塞进侧栏「热门文章」下面。

补齐 Mango 官方四个小工具的最后一块。

6. 说说详情页 + 独立互动

半天

现在说说只有列表，⋯ 跳到 /moments/#id。加 src/pages/moments/[id].astro 生成独立页，带 OG 图、评论、点赞，也是「单条说说」可分享的前提。

7. 邮件订阅

1 小时

RSS 之外给不想用阅读器的人一条路：Buttondown / follow.it 嵌入表单，或 Cloudflare Worker + Resend 自建。

8. 代码块体验

2 小时

右上角「复制」按钮 + 语言标签 + 可选行号。现在文章页只有「复制链接」，代码块里没有复制入口——技术博客的高频操作。

落点：src/styles/global.css 里 .prose pre 附近 + 一段内联脚本。

9. 图片 LQIP 占位

半天

构建期为每张图生成 20px 的 base64 缩略图或主色，作为 background-image 垫在 <img> 下面，图片到达时淡入。

图片博客的观感差异主要来自这里——从「白块逐个弹出」变成「先看模糊轮廓」。
P2 体验打磨与长期运营 按兴趣挑，随时可停

10. View Transitions + prefetch

1 小时

两行配置就能让站内跳转从「白屏刷新」变成原生 App 式的过渡，还能让侧栏音乐播放器跨页不断播。

注意：ClientRouter 会接管脚本执行，现有内联 <script> 需要改成 astro:page-load 事件，否则灯箱/目录在二次跳转后失效。

11. ⌘K 搜索弹层

半天

全局快捷键唤出搜索浮层，输入即出结果，↑↓ 选择、Enter 进入。比跳转 /search 顺手一个量级。

12. 移动端底部 Tab 栏

半天

朋友圈风格在手机上天然适合「首页 / 说说 / 收藏 / 我的」四宫格底栏，替代现在的汉堡抽屉。

13. 文章系列 / 专栏

半天

给 frontmatter 加 series 字段，文章底部渲染「本篇是《NAS 折腾记》第 3 篇」，自动生成系列目录页。

14. 长文分页

1–2 天

Mango 官方特性（演示站那篇 NAS 长文就是分页的）。用 <!-- pagebreak --> 切分，生成 /posts/xxx/2/。

15. 阅读体验细节

半天
  • 文章过期提示：「本文发布于 800 天前，部分内容可能已过时」
  • 字号调节（小/中/大，存 localStorage）
  • 打印样式：隐藏侧栏与浮动按钮，正文单栏

16. 无障碍补齐

2 小时
  • 「跳到主内容」skip-link（键盘 Tab 第一下出现）
  • 导航加 aria-current="page"
  • 浮动按钮组统一 :focus-visible 描边

17. PWA manifest + 离线

半天

加 manifest.webmanifest（图标、主题色、standalone），配一个极简 Service Worker 缓存壳与 404 兜底，手机可「添加到主屏」。

18. 主动推送收录

2 小时

IndexNow（Bing/Yandex 秒收录）+ 百度站长 API 推送。部署后自动跑一次，新文章几小时内进索引。

19. llms.txt

30 分钟

给 AI 爬虫一份站点结构说明（标题 + 摘要 + 链接），AI 搜索时代的基础礼貌。

20. GitHub Actions 自动部署

1 小时

现在每次都是手动 wrangler pages deploy。改成 push 触发：check:content → astro build → wrangler，PR 出预览环境。

顺带解决「改了忘部署」和「部署了忘检查」两个老大难。

05建议的实施顺序

不建议一次全上。按下面三批推进，每批结束站点都处于「可上线」状态。

01

第一批 · 半天到一天：把地基补平

P0 的 1、3、4、6、7（缓存头、图标子集、robots+sitemap、相关文章、搜索索引外置）。这五项互不依赖，可以并行做。

验收：首页传输从 1.06 MB 降到 < 700 KB；curl -I 看到 /_astro/* 带 immutable；robots.txt 里有 Sitemap 行。
02

第二批 · 两三天：图片管线 + 评论

P0-2（astro:assets 全量迁移、banner 压缩、srcset）+ P1-1（giscus 接入）。图片改动会碰到所有内容文件，适合单独一个提交；评论是纯增量，互不干扰。

验收：Lighthouse 移动端 Performance ≥ 90；文章页底部出现评论区且暗色正常。
03

第三批 · 按需：真实数据与体验

P1-2（浏览量/点赞）、P1-3（Pagefind）、P1-4（加载更多）挑着做；P2 里优先 View Transitions + prefetch（一小时见效）与 GitHub Actions（省心）。

验收：「热门文章」随真实访问变化；搜索能命中正文；push 即自动部署。

如果只想做一件事

做 图片管线。它是唯一同时改善「加载速度、CLS、移动端流量、长列表滚动流畅度」的一项，而且图片博客的成色几乎全押在图上。第二件事是评论——它决定这个站是「作品集」还是「博客」。
