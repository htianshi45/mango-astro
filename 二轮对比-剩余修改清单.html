Mango 主题 · 二轮对比（Qoder 改版后）剩余修改清单

对比对象：http://localhost:4321/（Qoder 已改过的 Astro 版，下称「本地 v2」）vs https://mango.huitheme.cn/（WordPress 原版，下称「原版」） 对照图：对比-原版vs新版.png（上为原版、下为本地 v2，上下拼接，同尺寸裁切 940px 宽） 生成时间：2026-11-06 ｜ 基准 CSS：Theme Version: 1.6.20241202 目标：一比一复刻，除静态站确实无法实现的功能外不做妥协

1. 一句话结论 🔍

Qoder 这轮把「骨架」搭对了：蓝色主色、900px 容器、#f7f7f7 背景、卡片/小工具的圆角与内边距、60px 缩进、侧栏三段顺序、深色页脚都到位了，整体观感从「另一个主题」变成了「同一个主题的粗糙版」。

但对照图里仍有 5 处「一眼假」：侧栏热门文章变成纯文字列表、轮播首帧不是原版那张图、文章九宫格塌成一行小图、顶栏 logo/图标体系完全不同、卡片底部三个数字全是 0。这 5 处不修，一比一就无从谈起。

估算达成度：约 65% → 做完 P0 约 85%，再做 P1 约 93%，剩余 7% 是 WordPress 动态功能（评论、点赞、浏览量、AJAX 分页），按第一轮清单约定的替代方案处理即可。

3. P0 · 一眼假，必须改 🚨

P0-1 侧栏「热门文章」首条大图整个消失（数据未接线）

现象：对照图里原版侧栏首条是「大图 + 渐变遮罩 + 白字标题 + 29条留言」，本地 v2 侧栏是 3 行纯文字。

根因（代码级）：src/pages/index.astro 里 postData 只映射了 5 个字段：

const postData = posts.map(post => ({
  title: post.data.title,
  slug: post.slug,
  timestamp: post.data.pubDate,
  views: post.data.views,
  excerpt: post.data.description,
}));

而 HotPostsWidget.astro 的大图分支条件是 index === 0 && post.heroImage，缩略图分支是 post.heroImage && …。heroImage 和 comments 根本没传进来，两个分支都不成立 → 只剩文字。且 my-first-photos.md 连 heroImage 字段都没有。

改法： 1. postData 补 heroImage: post.data.heroImage ?? post.data.images?.[0]、comments: post.data.comments ?? 0。 2. content/config.ts 补 comments、likes 字段；两篇示例文章补齐 heroImage / comments / 真实头像。 3. 按原版 DOM 重排 HotPostsWidget：<ul class="widget_hot_post"><li class="widget_hot_li">，首条 img{width:100%; margin:0}，.hot_post_info 绝对定位铺满 + :before 渐变遮罩（linear-gradient(to top,black,transparent), opacity:.6），其余条目 img{75px; margin-right:15px; border-radius:4px}、h4{13px; 2行截断}、p{12px; #9b9b9b}「N条留言」。 4. 本地当前是 h-[180px] 固定高 + space-y-3 + rounded + 14px 标题 → 与原版 400×280（比例 1.43）不符，需改。

P0-4 顶栏：logo、图标体系、导航死链

  1. Logo：原版是 202209211355582.png（橙黄芒果圆形图，30px 高）+ <b>Mango</b>；本地 public/images/logo.svg 是蓝色圆 + 白字 M，对照图里非常显眼。换成本地自绘的等价图标（不要直接下载商用图，见第 8 节）。
  2. 图标字体缺失：原版全站用 Bootstrap Icons（bi-palette / bi-search / bi-three-dots / bi-hash / bi-chat-square-text-fill / bi-eye-fill / bi-heart-fill / bi-chevron-*），本地一律 inline SVG → 线条粗细、造型全不一样，这是全站性视觉差异。建议自托管 bootstrap-icons 字体到 public/fonts/，统一改用 <i class="bi bi-xxx">。
  3. 导航死链：本地 /categories/风景、/categories/科技、/download、/map 在 src/pages/ 下全部不存在，点了必 404。原版菜单还有「旅拍」前的 bi-palette 图标、「科技」下拉里的子项（原版含「旅拍」），本地子项写成了「数码/软件」。→ 至少补出对应静态页或改成 /tags/xxx 有效路由。
  4. 右侧按钮：原版是 bi-search + .theme-switch（30×30 圆、#e9e9e9 底、暗色下 #ffc008 图标）；本地是 20px SVG + 月亮图标，且 p-2 rounded-lg，没有圆形底。
  5. 搜索形态：原版 #c_sousuo 是从顶部展开的 120px 高搜索条（.ss_a 3px #ddd 边框、40px 行高、右侧搜索按钮）；本地是右侧滑入 offcanvas，且提交按钮没有任何事件（假表单）。详见 P1-9。

4. P1 · 结构与功能，第二眼才发现 ⚠️

P1-6 分页没接线，样式也不对

  • src/components/Pagination.astro 已创建但全工程无任何 import（全局搜索 Pagination 只命中它自己），本地首页一次性列出全部文章。
  • 原版：.posts-nav{text-align:center;margin:40px 0}，.page-numbers{padding:5px 10px; background:#fff; color:#555; font-size:12px; margin:0 2px} —— 无圆角、无边框；.current/:hover{background:#4270f6; color:#fff}。本地是 rounded border 圆角描边按钮 +「← 上一页 / 下一页 →」文字。
  • 原版还有 post-read-more（AJAX 加载更多）。静态站实现：用 Astro paginate() 生成 /page/2/，或退而求其次做静态页码 + 每页 8 篇；暗色下页码底为 #2a2a2b。

P1-7 文章详情页结构完全不是一回事（差距最大）

原版是三段分离白卡 + 评论区：

区块 原版 CSS
.post_container_title padding:25px 30px 20px; border-bottom:2px solid #f7f7f7; border-radius:4px 4px 0 0; h1 20px; p 12px（含分类/日期/浏览/评论 span + 图标）
.post_container padding:30px 32px 20px; border-radius:0 0 4px 4px（正文）
.post_author margin-bottom:20px; padding:20px 30px; border-top:3px solid #f7f7f7; border-radius:0 0 4px 4px; flex; space-between；头像 28×28；右侧 .post_author_icon a 蓝底白字 4px 8px / radius 4px / 12px
.post_related / #comments 相关文章列表 + 评论表单/列表

本地 [slug].astro 把标题、作者、分享、图片、正文、标签、元信息全塞进一个 .post-loop 卡片；post_container_title、post_author 这两个 class 在 global.css 里根本没有定义，是死 class；没有评论区、没有上一篇/下一篇；「相关文章」是写死的两条假数据且 href="/"；图片画廊被放在正文之前（原版正文内插图）。→ 建议按三段卡重做，评论区用 Giscus/Twikoo 接入（第一轮清单已约定）。

P1-8 侧栏三个小工具的细节

  • 缺 .sidebar_sticky{position:sticky; top:95px; margin-bottom:20px} → 原版滚动时侧栏吸顶跟随，本地不会。
  • 热门标签 hot 圆点位置反了：原版 .tagcloud a.hot:before{12×12; top:-2px; right:0px; border:3px solid #fff}（右上）；本地 TagsWidget.astro 是 -left-1 -top-1、w-3 h-3、border-2（左上）。暗色下原版边框变 #212121。另外原版 hot 是按后台标记，本地改成按 tag 出现次数取前 3，可以保留但要在文档里说明。
  • 最近评论结构反了：原版 <li> 是「头像 + 评论正文（13px 两行截断）+ <span><em>昵称</em><em>发布于4 月前</em></span>」，且 padding-bottom:15px; border-bottom:1px solid #f4f4f4; margin-bottom:15px；本地是「访客 A：内容 + 文章标题 - 日期」，无分隔线，只有 2 条 mock（原版 5 条）。头像 24×24 ✅。

P1-9 搜索是假的

Header.astro 的 #search-overlay 里 <input> + 「搜索」按钮没有任何提交逻辑、无结果页。建议接 Pagefind（静态索引，中文分词限制见 Firefly 那次的结论，可用 @pagefind + 自定义分词）或至少做一个 /search 页过滤 frontmatter；同时把形态改成原版顶部 120px 搜索条。

P1-10 背景纹理 + 主内容区间距

  • 原版 --ds_background 是站点自带 SVG（/wp-content/uploads/2022/11/2022112916111665.svg），水波纹明显；本地是 inline data-URI M0 50 Q25 30 50 50… 100×100 平铺、stroke-width:0.5，对照图里几乎看不出纹理。→ 自绘一张等价的浅灰波纹 SVG 放 public/images/。
  • BaseLayout.astro 的 <main class="… px-4 py-6 max-w-mango"> 多了 px-4(16px) 与 py-6(24px)；原版 header 自带 margin-bottom:1.5rem、.index_banner{margin-bottom:25px}，主区没有额外上下 padding → 本地首屏整体比原版「松」一截。建议去掉 py-6，保留必要横向留白并核对 900px 内含 padding 后的实际内容宽。
  • 原版 body{background-attachment:fixed} ✅ 已有；暗色 background-blend-mode:overlay 本地缺。

P1-11 页脚与返回顶部

  • 原版页脚 .copyright 两行：主题版权 + ICP 备案号链接 .beian；另有一个独立的 .links{background:#272b30; padding:25px 0; 12px; 居中} 友情链接块。本地是「© 2026 Mango Theme / Powered by Astro / 友情链接 | 网站地图」，其中两个链接都是 # 空链接，且没有 .links 块。
  • .scrollToTopBtn：原版 48×48 纯黑圆、bottom:30px; right:30px、opacity:0 + translateY(100px) → .showBtn 显示、hover #4270f6；本地 BackToTop.astro 是蓝色底 + bottom-8 right-8(32px) + 阴影 + 箭头 SVG。改黑底、去阴影、位置改 30px。

P1-12 暗色模式覆盖不全

原版 .dark 规则是成体系的（.post_loop/#212121、.post_loop_tag em/#343435、.widget-title:after/#191919、.posts-nav .page-numbers/#2a2a2b、.footbox/#151516、.links/#1d1d1d、#c_sousuo/#1a1a1a 等）。本地只有 global.css 少量 + 各组件零散 dark:，Footer.astro、Banner.astro、BackToTop.astro 完全没做暗色适配。建议把原版 .dark 段落整体映射成一份 .dark … 规则表，别再靠每个组件手写 Tailwind dark:。
